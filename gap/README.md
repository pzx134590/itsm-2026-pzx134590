# Client-server latency gap

The client and server p99 values describe different portions of a request. The server histogram starts when svcdesk begins handling the request and stops when its response is ready, so it includes the knowledge-index call but not time spent waiting for the response to travel back to the client. The client timer includes connection and network time as well as the server's work. In this experiment Toxiproxy adds a downstream latency toxic after svcdesk has produced its response. The extra delay should therefore raise the client's p99 while leaving the server histogram's p99 nearly unchanged. Random variation, scheduling, and interpolation in the histogram can make the measured difference differ from the configured latency; jitter makes individual responses vary as well. With a 100 ms toxic and 10 ms jitter, one run measured a client p99 of 0.2875 s and a server histogram p99 of 0.1769 s, for an observed gap of 0.1106 s. Those are rounded run values, not guarantees for a future run. The gap is an observed difference between two p99 values, not a claim that every request receives exactly the same added delay.
